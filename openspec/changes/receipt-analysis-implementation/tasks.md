## Key Learnings

1. Excluding generated fixture bytes (`samples/images/*`, vendored font) from the authored-line budget count is necessary or every slice would misleadingly forecast High risk from binary assets alone.
2. Slice 1's fixture-authoring work (`generate.py` + `manifest.json` + 3 image fixtures) is real net-new authored code, not boilerplate, and independently risks the 400-line budget even before ingestion logic is counted.
3. Slice 4 concentrates the largest authored surface (scoring engine + full API adapter + docs mirror + contract/privacy/determinism tests) and is the most likely candidate for an unplanned further split if the real diff confirms the High forecast.
4. Every `INCONCLUSIVE`/confidence test must assert the whole-request coverage formula, never a per-analyzer shortcut, to structurally lock out the exact bug the product owner rejected.
5. The two known-answer fixtures (CBU `2850590940090418135201`, CUIT `20-17254359-7`) from the proposal must appear as literal RED test cases in slice 3a before any validator implementation.
